Install and run Stand scripts

Install third-party Stand scripts in the correct folder, load them, and troubleshoot compatibility errors.

Updated September 23, 2026

Premium includes a Stand compatibility layer for third-party Stand scripts. Use the dedicated Stand folder so the menu selects the correct loader. Support for a script depends on the APIs it uses; compatibility does not mean every Stand feature is implemented.

Install your script

Stand user-script folder — paste into File Explorer
%LOCALAPPDATA%\Nenyoo\Plus\Scripts\User\stand\
  1. 1
    Open the user-script folder

    Use Open Scripts Folder in the menu, then open the stand subfolder. Create that subfolder if it is missing, or paste the complete path above into File Explorer.

  2. 2
    Extract the script or package

    Put a single .lua or .pluto file in the Stand folder. For a multi-file package, extract the complete package folder there and preserve its helper files and subfolders.

  3. 3
    Keep Stand scripts out of the native folder

    Do not put them directly in Scripts/User/. Scripts outside the stand folder use the native Nenyoo loader instead of the Stand compatibility layer.

TipNo marker needed

Routing is based on the folder, not recognizable API calls. Do not add -- @nenyoo-menu to a Stand script. Obfuscated or packed scripts still use the Stand loader when they are inside Scripts/User/stand/.

Load and run the script

  1. 1
    Refresh the script list

    After copying the files, open the menu’s script manager and choose Refresh Script List to rescan. Refreshing the list does not run scripts.

  2. 2
    Select the script and load it

    Find the script under Installed Scripts, open its entry, and choose Load. Once loaded, use Open Script to access its feature menu.

  3. 3
    Reload after edits

    Use Reload All Loaded to reload scripts that are already running. Use Unload on a script’s page to stop it and release its resources.

Multi-file packages

Keep a package together inside its own folder under stand. In a recognized package, helper files stay private and the entry script is listed. For a fully obfuscated folder without recognizable entry markers, multiple files may appear as separate entries because their roles cannot be identified before they run. Follow the package author’s instructions to select the entry point.

Do not edit the compatibility layer

Internal API files — not a place to install user scripts
%LOCALAPPDATA%\Nenyoo\Plus\Scripts\Lib\Api\stand\

This folder contains the Stand compatibility layer. Do not install scripts here, overwrite it with a script package, or modify its files to fix a script error.

If the script does not work

  • Check that the script is really under Scripts/User/stand/, not the native user folder or internal API folder.
  • Extract archives before refreshing the list, and keep the script’s required helper files with it.
  • A Stand Script Error means the script started but encountered a runtime error. Record the complete message and script name.
  • Some compatibility functions are placeholders or no-ops: a script may load while a particular feature does nothing.
  • If it still fails, ask in Discord with the script name, reproduction steps, and exact error. Use Collect logs and report a bug for log locations. Do not post paid or private script source without permission.

Writing a new script? Use the native Engine + Foundation API in Your first Lua script and the Lua API reference. The Discord Stand-script guide ↗ provides the original installation guidance.
