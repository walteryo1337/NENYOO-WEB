Hypervisor / VBS is running

Troubleshoot the Windows hypervisor, VBS, and Memory Integrity warning, and collect a diagnostic report.

Updated September 23, 2026

Heads upBefore changing Windows settings

Turning off VBS, Memory Integrity, or the Windows hypervisor reduces Windows protections and can stop WSL2, Docker Desktop, Sandbox, and virtual machines from working. Save your work and BitLocker recovery key, record your original settings, and ask your administrator before changing a managed device.

Why this warning appears

The loader checks whether VBS (virtualization-based security) or HVCI (Memory Integrity) is running. A Windows hypervisor can remain active even when you are not using a virtual machine. Hyper-V features, Credential Guard, device policies, or OEM settings can keep VBS enabled.

  1. 1
    Save your work first

    The loader’s Disable & Reboot button changes Windows security / boot settings and restarts the PC. In the current loader it also disables the vulnerable driver blocklist. Review these effects before using it; this action reduces Windows protections.

  2. 2
    Use the loader’s Disable & Reboot option if you choose that route

    If the button is shown and you accept those changes, use it and let Windows restart. This is a system change, not just a diagnostic check.

  3. 3
    Check again after reboot

    Reopen the loader. If the banner remains, collect the diagnostic report below and work through the manual checks. Repeatedly pressing the button will not override every firmware or organization policy.

Manual hypervisor and VBS checks

Use an administrator account on your own PC. If this is a work or school device, contact its administrator before changing managed settings. Follow the separate BitLocker guide and record the original values before changing boot or registry settings.

  1. 1
    Open PowerShell as administrator

    Open Start, search for PowerShell, right-click it, and choose Run as administrator. Run the command below to stop the Windows hypervisor from launching on the next boot.

Administrator PowerShell — disable hypervisor launch
bcdedit /set hypervisorlaunchtype off

Restart Windows to apply this change. If you are also making the VBS registry change below, finish it first and then restart once. If the command fails, include the exact error in your support ticket instead of assuming it worked.

  1. 1
    Check the VBS registry value

    Press Win + R, enter regedit, and open Registry Editor. Paste the path below into its address bar. Export the key as a backup and record its original value before editing.

Registry Editor address bar
HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Control\DeviceGuard

Set EnableVirtualizationBasedSecurity to 0. If it is absent on your personal, unmanaged PC, create a DWORD (32-bit) Value with that name and set it to 0. Change only this value; do not delete the DeviceGuard key or other security policies. Restart Windows, then verify the runtime state again.

  1. 1
    Check Memory Integrity

    Open Windows Security → Device security → Core isolation details and set Memory Integrity to Off for this setup. Restart after changes. Core isolation is the settings area; Memory Integrity is the individual switch.

  2. 2
    Review optional Windows features if VBS returns

    Press Win + R, enter OptionalFeatures.exe, and review Hyper-V, Windows Hypervisor Platform, Virtual Machine Platform, Windows Sandbox, and Windows Subsystem for Linux, where available. If you choose to disable these features for this loader mode, restart afterward. WSL2, Docker Desktop, Sandbox, and virtual machines may stop working until their required features and virtualization are restored.

  3. 3
    Check firmware virtualization again

    If VBS remains active, return to UEFI and check Intel VT-x / VT-d or AMD SVM / IOMMU using the motherboard examples in the Secure Boot guide. Do not change unrelated firmware settings.

Credential Guard does not have a universal “Off” switch in Device Security. Its configuration may require Group Policy, Intune, or registry changes, and a UEFI-locked configuration has extra requirements. Follow Microsoft’s Credential Guard instructions ↗ or ask your administrator. On managed devices, rsop.msc can help an administrator inspect applied Device Guard policy; it is not available on every Windows edition.

Heads upWhen settings are managed or keep coming back

Group Policy, Intune, Credential Guard with UEFI lock, and some OEM secured-core configurations may enforce VBS. Do not delete Windows security policies, clear firmware keys, or reset the TPM to force a change. Send the diagnostic output to support or your device administrator.

Download the VBS diagnostic tool

check_vbs.bat — VBS / HVCI diagnostic

Reads Windows security state and saves a text report for your Discord ticket. It does not change boot settings, registry values, or security features.

Download
  1. 1
    Download and run as administrator

    Save check_vbs.bat, right-click it, and choose Run as administrator. Administrator rights are needed for complete diagnostic information. You can inspect the BAT in a text editor first.

  2. 2
    Read the VERDICT section

    The report shows the WMI runtime check, registry configuration, and extra boot / Hyper-V context. If WMI fails, the result is marked INCONCLUSIVE; registry configuration alone cannot prove whether VBS is running.

  3. 3
    Attach the report to your Discord ticket

    The tool displays the output and saves Nenyoo-vbs-check.txt in your temporary folder. Open the path below, review the report, and attach the text file to your Discord support ticket along with the loader error and relevant logs. See Collect logs and report a bug.

Saved diagnostic report — paste into File Explorer or Run
%TEMP%\Nenyoo-vbs-check.txt

Understand the diagnostic result

CLEAN (WMI)WMI does not report VBS or HVCI running. This checks those features only; it does not certify every loader requirement.
TRIGGERVBS is running, or HVCI is running while VBS is active. Include the full report in your ticket.
INCONCLUSIVEWMI failed. The registry fallback shows configuration, not confirmed runtime state. Send the full output to support.

VirtualizationBasedSecurityStatus: 0 = not enabled; 1 = enabled but not running; 2 = enabled and running. The loader’s runtime VBS trigger is 2. SecurityServicesRunning containing 2 is the HVCI / Memory Integrity signal; the loader also checks that VBS is running.

SecurityServicesRunning codes: 0 = none, 1 = Credential Guard, 2 = Memory Integrity, 3 = System Guard Secure Launch, 4 = SMM Firmware Measurement, 5 = kernel hardware-enforced stack protection, 6 = its audit mode, 7 = hypervisor-enforced paging translation. CodeIntegrityPolicyEnforcementStatus describes code-integrity policy enforcement; it is not the loader’s HVCI trigger. Do not treat its value of 2 alone as proof that Memory Integrity is running. Microsoft’s runtime-status reference ↗.

Restore your settings later

Administrator PowerShell — restore normal hypervisor launch
bcdedit /set hypervisorlaunchtype auto

Restore the original registry value (or remove only the value you created if it was originally absent), firmware options, and Windows security settings you recorded. Restoring the hypervisor launch command alone does not restore every protection. Use the same firmware and Windows Security screens to restore the settings you recorded. Re-enable virtualization if you need virtual machines, WSL2, Docker Desktop, or Sandbox, then restart. Your PC may need these settings changed again before using this loader mode.
